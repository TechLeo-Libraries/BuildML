# cost-sensitive-collections

## Business purpose
Choose contact / collection actions under FP/FN costs and capacity constraints.

## Data source
Synthetic / in-script license-clear data generated by `script.py`.

## Leakage controls
- Proper split before fit (random / group / time as domain requires)
- Train-only fitting and selection
- Holdout evaluation after model lock
- Test never used for selection

## BuildML API steps
1. classical fit → fit_decision_policy(threshold/knapsack) on validation
2. evaluate_decisions on test
3. bundle
