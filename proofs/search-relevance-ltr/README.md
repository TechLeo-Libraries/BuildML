# search-relevance-ltr

You have graded relevance judgments per query. You want a ranker that does
not leak queries across partitions, then query-averaged nDCG on held-out
queries.

## Data

Synthetic / in-script license-clear judgments generated by `script.py`.

## Leakage

`group_split` on the query id before fit. The ranker learns from train only.
Test `session.ranking.rank` / `session.ranking.evaluate` run after lock.

## How to run

```bash
python proofs/search-relevance-ltr/script.py
python proofs/search-relevance-ltr/baseline_industry.py
```

## What you'll get

`results/results.json` with ranking metrics (nDCG@k).
`results/comparison.json` is pointwise Ridge on the same `group_split`,
reporting query-averaged nDCG@5. LambdaRank is used when LightGBM is
available, else pointwise.

## Limitations

Synthetic judgments.
